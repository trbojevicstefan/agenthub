# Connect OPAYA agents to Cord AI

## Desktop

1. In Cord, choose **Connect Agent → OPAYA** and copy the generated prompt.
2. In OPAYA, choose **Home → Connect to Cord AI**.
3. Paste the prompt, select an existing agent, and click **Connect Agent**.

The background bridge connects outbound to Cord. The native authenticated OPAYA service retains the selected agent’s Vault credentials, MCP servers, remote machines/containers and permission settings. Each Cord thread/DM gets its own persisted OPAYA conversation. Cord receives the agent’s answer; the Vault is not exported. Keep OPAYA’s session service running.

The helper extracts only runtime source files into the profile’s `cord-runtime` folder, so it works from packaged app.asar without asking system Node to read Electron archives. No user data is included. The bridge requires Node 22.13+ (system or OPAYA’s toolchain); Electron’s Node mode is the fallback.

## CLI / prompt

```sh
npm run cord:connect -- --list
npm run cord:connect -- --server https://cord.example --pair CODE --runtime opaya --opaya-agent AGENT_ID
```

`--opaya-profile DIR` selects a nonstandard desktop profile. Without the OPAYA service, compatible local runtime definitions can be invoked directly. For Claude Code, Codex, Hermes or OpenClaw on a computer without OPAYA, the prompt generated by Cord downloads its standalone bridge instead. Both paths share the transport code; the AgentHub version imports the native `desktop/adapters/` modules directly.

Connection files, local logs, locks, session mapping and status live under `~/.cord/agents/ID` (or `CORD_HOME`). The installer prints exact `--config PATH --status`, `--stop` and `--start` commands. Tokens belong only in those private local files, never in Git or chat. Pairing codes are single-use and expire after 15 minutes. Bridge startup after reboot uses the printed start command or a user service manager; login startup is not installed automatically.

## Cord controls

The agent appears as a teammate. Mention it in a channel, assign it to a thread, or open a DM. Cord admins can set display name, description, model, instructions, reasoning effort and timeout; test, pause, reconnect or revoke access; inspect jobs; and cancel running work. Native OPAYA tool approvals continue to appear in OPAYA. Direct Codex/ACP adapters use Cord approvals. Existing runtime trust settings are preserved, not silently broadened by the bridge.

For remote agents Cord needs a reachable HTTPS origin. Localhost prompts work only on the same computer. Model/provider credentials remain the runtime’s responsibility; pairing alone does not verify a paid inference request.

## Validation

`tests/cord-bridge.test.cjs` covers secure destinations, command argument handling, desktop connection validation, pairing a selected native definition, and session reuse through the authenticated local OPAYA socket. Cord’s integration suite also executes the HTTP adapter end-to-end against a local test gateway. These tests do not call paid models.
